# Daily World & Markets Briefing — Design

**Date:** 2026-09-25
**Status:** Draft, awaiting review

## 1. Purpose

A private daily briefing so the owner stays informed about the most important world news and the stock market. It is not a public channel, has no audience, and isn't meant to build a brand.

**Success criteria**
- Arrives every day by 07:00 Europe/Berlin, including when the owner's PC is off.
- It's a 10–15 minute read on the web page, and the email digest takes about 2 minutes.
- Market numbers and charts are always from real data and never generated by the model.
- Every story traces back to real source headlines with links.
- Running cost: $0 extra (it uses the owner's existing Claude subscription and free GitHub tiers).

**Decisions made during brainstorming**

| Topic | Decision |
|---|---|
| Delivery | Email (Gmail) + web page (GitHub Pages) |
| Market scope | US-focused in depth + global snapshot (Europe, Asia, FX, commodities, crypto) |
| Timing | Morning edition, 07:00 Europe/Berlin |
| Length | 10–15 minute read (page), ~2-minute digest (email) |
| Runtime | GitHub Actions on a schedule |
| AI | Claude Code GitHub Action, model `claude-sonnet-5`, authenticated with the owner's subscription (`CLAUDE_CODE_OAUTH_TOKEN`) |
| Page visibility | Public repo + public-but-unlisted GitHub Pages site (content is public news only) |
| Local path | `C:\Users\nitsc\Projects\daily-briefing` + a project note in the Obsidian vault |

## 2. Architecture

A pipeline of four stages in one GitHub Actions workflow. Each stage communicates through files in `data/YYYY-MM-DD/`, so any stage can be re-run or tested on its own.

```
1. COLLECT (Python)  → data/<date>/input.json
2. WRITE   (Claude)  → data/<date>/briefing.json
3. RENDER  (Python)  → site/<date>/index.html, site/index.html, site/archive.html, data/<date>/email.html
4. PUBLISH           → commit data/ + site/, deploy Pages, send email
```

**Core principle:** Python owns every fact and number, and Claude only selects and explains. Tables and charts are rendered straight from collected data. Claude's output refers to headlines by ID, and the validator checks those references.

### 2.1 Collect (`briefing/collect_*.py`)

- **`collect_news.py`**: fetches the RSS feeds listed in `config.yaml` (around 20: Reuters, AP, BBC World, FT, Bloomberg, CNBC, Al Jazeera, Nikkei Asia, DW, the Guardian and similar, trimmed to feeds that are reachable). Keeps items from the last 24 hours. Removes duplicates by normalised title similarity and merges items about the same event into one entry, keeping all its source URLs. Caps the result at ~300 headlines. Each headline gets a stable ID (`h001`…), with title, summary/description (truncated), source, URL and published time.
- **`collect_markets.py`**: uses `yfinance`. Tickers are set in `config.yaml`:
  - US: `^GSPC`, `^IXIC`, `^DJI`, `ES=F`, `NQ=F`, `^VIX`, `^TNX`
  - Europe: `^GDAXI`, `^FTSE`, `^STOXX50E`
  - Asia: `^N225`, `^HSI`, `000001.SS`
  - FX/Commodities/Crypto: `EURUSD=X`, `JPY=X`, `DX-Y.NYB`, `CL=F`, `BZ=F`, `GC=F`, `BTC-USD`
  - For each: last value, absolute and % change, timestamp of the last value, and 30 days of daily closes.
  - **US movers:** the 5 biggest gainers and 5 biggest losers in the S&P 500 for the last session (constituent list stored in the repo, refreshed by a manual script).
- **`collect_calendar.py`**: today's economic releases and major earnings. Source to be confirmed during planning, with a free option required (e.g. a public economic-calendar feed, and yfinance earnings dates for large caps). If none is reliable, this section can be left out without breaking anything.
- Output: `input.json` with `news[]`, `markets{}`, `movers{}`, `calendar[]`, `meta{generated_at, feed_success_count, feed_total, errors[]}`.

### 2.2 Write (Claude Code Action)

- Step: `anthropics/claude-code-action@v1`, automation mode (with a `prompt` input).
- `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`
- `claude_args: --model claude-sonnet-5 --max-turns 6 --allowedTools "Read,Write"`. No web access and no shell.
- The prompt points to `prompts/writer.md` plus the day's `input.json`, and asks Claude to write `briefing.json` following the schema in §3.
- Step timeout: 10 minutes.

### 2.3 Render (`briefing/validate.py`, `briefing/render.py`)

- **Validate:** parse `briefing.json` against the schema. Drop any story whose `headline_ids` don't all exist in `input.json`. Log whatever was dropped. If the file is missing or invalid → **raw edition** (§4).
- **Render:** Jinja2 templates.
  - Page: charts as inline SVG generated in Python, so there's no JavaScript dependency and they work offline and in the archive. The page is self-contained HTML with light/dark support.
  - Email: HTML with inline styles, tables only, no charts. It includes a plain-text fallback part.
  - Updates `site/index.html` (latest) and `site/archive.html` (list of all past editions).

### 2.4 Publish

- Commit `data/` and `site/` to `main` (this also keeps the scheduled workflow active; GitHub disables schedules in public repos after 60 days without activity).
- Deploy `site/` to GitHub Pages using the Pages deployment action. The repo's `docs/` folder is **not** served, so specs and plans stay out of the site.
- Send the email over Gmail SMTP (`smtp.gmail.com:587`, STARTTLS) using the `GMAIL_ADDRESS` and `GMAIL_APP_PASSWORD` secrets. The recipient is `BRIEFING_TO` (a secret, so the address isn't in the public repo).

## 3. Briefing content

### 3.1 `briefing.json` schema (what Claude writes)

```json
{
  "date": "2026-09-26",
  "headline": "one-line headline for the day",
  "at_a_glance": ["5 bullets"],
  "market_analysis": "2–3 paragraphs",
  "mover_notes": {"TICKER": "one-line reason, only if the news explains it"},
  "stories": [
    {
      "section": "Geopolitics | Economy & Policy | Business & Tech | Other",
      "title": "...",
      "summary": "3–4 sentences",
      "why_it_matters": "1–2 sentences",
      "headline_ids": ["h012", "h047"],
      "single_source": false
    }
  ],
  "watch_today": ["3 items"]
}
```
8–10 stories.

### 3.2 Web page order

1. Header: date, headline, estimated reading time
2. At a glance: 5 bullets
3. Markets: US table (value, change, % change coloured green/red) and a compact global table with sparklines, an S&P 500 30-day chart, US movers with notes, and the market analysis
4. World news: stories grouped by section, each with summary, "Why it matters" and source links
5. Today's calendar: shown in Europe/Berlin time
6. Watch today
7. Footer: archive link, "data as of HH:MM CET/CEST", "not investment advice"

### 3.3 Email

- Subject: `☀ <Mon DD> · <headline>`
- Body: at-a-glance bullets, market snapshot table, story titles with "why it matters", and a "Read the full briefing →" button linking to the day's page.

### 3.4 Editorial rules (`prompts/writer.md`)

- Neutral, factual tone, with no hype and no political opinions.
- Only report events that appear in the input headlines. Every story cites `headline_ids`.
- Set `single_source: true` when only one outlet reports the story (shown as "single-source report").
- No buy/sell recommendations or investment advice.
- Rank by global importance and market relevance, not by how many outlets repeated the story.

## 4. Error handling

| Failure | Behaviour |
|---|---|
| Some feeds fail | Skip them. If fewer than 50% succeed, show a banner: "⚠ Limited sources today". |
| A ticker fails | 3 retries with backoff, then show "–" and leave out its chart. Never estimate a value. |
| All market data fails | News-only edition with a banner. |
| Claude step fails, times out or produces invalid output | Retry once. If it still fails, publish a **raw edition**: market tables, charts and the top ~15 headlines as links, with a banner "AI summary unavailable today". |
| A story references an unknown headline | Drop the story and log it. |
| Email send fails | The page still publishes. The job is marked failed, so GitHub's failure notification emails the owner. |
| The workflow never runs or crashes | GitHub's failure notification. Manual re-run via `workflow_dispatch`. |

**Scheduling**
- Two cron entries, `15 4 * * *` and `15 5 * * *` (UTC). A first step keeps going only if the current Europe/Berlin hour is 06, which handles the CET/CEST switch.
- Idempotency: if `site/<today>/index.html` already exists and was emailed (marker file `data/<date>/sent`), skip. `workflow_dispatch` has a `force` input to override this.
- Expected arrival: ~06:20–06:45 Berlin time, which leaves room for GitHub's scheduling delays.

**Usage limits**
- `--max-turns` plus a 10-minute step timeout. About 15k input and 10k output tokens per day.

## 5. Configuration (`config.yaml`)

Feeds (name, URL, region), ticker groups, the S&P 500 constituent file path, model name, number of stories, timezone, site base URL. Switching to API billing would mean replacing the `claude_code_oauth_token` input with `anthropic_api_key`, which is a one-line change in the workflow.

## 6. Repository layout

```
daily-briefing/
├─ briefing/            collect_news.py, collect_markets.py, collect_calendar.py,
│                       validate.py, render.py, send_email.py, charts.py, raw_edition.py
├─ prompts/writer.md
├─ templates/           page.html.j2, email.html.j2, archive.html.j2
├─ config.yaml
├─ data/<date>/         input.json, briefing.json, email.html, sent
├─ site/                published by GitHub Pages
├─ tests/               fixtures/ + unit tests
├─ scripts/dry_run.py   runs the full pipeline locally, no publish/email
├─ docs/superpowers/    specs and plans (not published)
└─ .github/workflows/daily.yml
```

Python 3.12, dependencies: `feedparser`, `yfinance`, `jinja2`, `pyyaml`, `pytest`.

## 7. Testing

- **Unit tests (pytest, offline, with fixtures):** removing duplicate news items, market parsing with missing tickers, the validator dropping stories with unknown IDs, schema errors leading to the raw edition, rendering the page/email/archive from fixture data, the Berlin-hour gate logic, and SVG chart generation.
- **Local dry run:** `python scripts/dry_run.py` collects live data, calls the local `claude` CLI (`claude -p --model claude-sonnet-5`) with the same prompt, renders, and opens the page in a browser. It doesn't commit or send email.
- **Live verification:** manual `workflow_dispatch` runs that check the email and page, before the schedule is turned on.

## 8. One-time setup (owner does this, with guidance)

1. Create a GitHub account (if needed) and a public repo `daily-briefing`.
2. Run `claude setup-token` locally and add it as the repo secret `CLAUDE_CODE_OAUTH_TOKEN`.
3. Turn on Google 2-step verification, create a Gmail app password, and add the secrets `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD` and `BRIEFING_TO`.
4. Repo Settings → Pages → Source: GitHub Actions.

Secrets are entered by the owner only.

## 9. Out of scope (for now)

Personal watchlist/portfolio, an evening edition, a podcast/audio version, and delivery via Obsidian notes. Any of these can be added later through `config.yaml` or a new render target.
